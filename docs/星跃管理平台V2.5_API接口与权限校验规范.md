# 星跃管理平台 V2.5｜API 接口与权限校验规范

> 状态：接口安全与兼容性基线。不是当前 API 已实现情况的证明。
> 实际路由、字段、认证方式必须以当前 Worker 源码和前端调用为准。

## 1. 总原则

1. Worker 是授权判定的可信边界；前端按钮、路由守卫和隐藏菜单不能代替服务端鉴权。
2. 不得仅凭客户端传来的 role、level、vip、owner_id、user_id 等字段信任身份。身份必须来自服务端验证的会话/令牌和数据库状态。
3. 每个读取和写入接口都必须验证资源归属、管理者边界和资源状态，防止 IDOR/BOLA。
4. 保留现有 API 路径、请求/响应字段及前端兼容性；改变契约前必须先检索所有调用方并给出迁移计划。
5. 错误响应不得泄露订阅凭证、内部堆栈、SQL、密钥或其他用户数据。
6. 生产部署必须获得用户明确授权。

## 2. 每个端点的权限检查清单

按接口实际动作逐项检查：
- 身份认证：当前会话是否有效、是否撤销、是否过期。
- 用户状态：账号是否冻结/禁用。
- 用户等级：L0/L1/L2/超级管理员。
- 管理身份：是否为体验 VIP 管理员或正式 VIP 管理员。
- VIP 状态：是否在有效期内，是否处于宽限/过期状态。
- 动作权限：read/create/update/delete/copy/share/activate/revoke 等是否允许。
- 资源归属：资源是否属于当前用户或当前 VIP 管理员。
- 资源状态：是否已删除、撤销、过期、归档或被锁定。
- 范围限制：分组、卡密、批次、工单、分享链接之间的关联是否合法。
- 风险控制：限流、幂等、防重放和异常请求检测。
- 审计要求：敏感操作是否记录操作者、目标、时间、结果和原因。

## 3. 身份与权限的服务端解释

- L0 未注册：只开放明确批准的基础转换和本人结果访问。
- L1 注册用户：开放注册用户已授权能力。
- L2 普通 VIP：开放 VIP 转换权益，不自动获得 VIP 管理员权限。
- 体验 VIP 管理员：有效期内开放核心 VIP 管理权限；到期后严格只读，复制权限待确认。
- 正式 VIP 管理员：有效期内开放核心管理权限；到期后按已确认规则允许查看和删除本人历史数据，但不允许新建/编辑需要有效 VIP 的管理业务。
- 超级管理员：最高管理权限，但所有敏感操作仍需审计。

不得把体验 VIP 和正式 VIP 合并成无法区分的一个身份状态；也不得把 VIP 管理员误建成 L3 等第四普通等级。

## 4. 数据归属与越权防护

- 所有资源读取和修改都必须在服务端查询中带入已认证的 owner/user scope。
- 禁止先按客户端传入 ID 查询全局记录，再仅在前端判断归属。
- 嵌套资源必须同时验证父子关系，例如卡密属于哪个管理员、节点属于哪个分组、批次属于哪个用户。
- 批量接口逐项验证所有资源归属；不能因为第一条合法就放行整个批次。
- 不存在与无权访问的资源，可采用一致的错误语义，避免泄露资源是否存在。
- 超管跨用户访问敏感数据仍需记录审计目的和操作范围。

## 5. 写操作、幂等和并发

- 对卡密激活、支付确认、转换任务创建、额度扣减、分享变更和归档等操作使用服务端幂等机制。
- 重复 request_id 应返回原任务结果，不重复创建任务或扣额度。
- 状态变更必须检查前置状态，并通过事务/条件更新防止竞态。
- 不接受客户端自行声明“已支付”“已激活”“已归档”“VIP 有效”等可信状态。
- 对批量操作提供明确的部分成功/失败结果，不能隐藏失败项。
- 删除、撤销和恢复必须记录原因及操作者。

## 6. 订阅凭证与链接安全

- 完整订阅 URL、令牌和节点认证信息不得出现在普通日志、错误消息或公开 API 响应中。
- 默认仅返回业务所需的脱敏字段；确实需要显示完整敏感信息时，必须有独立权限和审计。
- 新生成的分享/转换令牌必须具有足够随机性，不可预测。
- 日志中只记录必要的令牌摘要或不可逆标识，不记录完整令牌。
- 分享链接应具备撤销、有效状态、访问控制和合理频率限制。

## 7. 错误响应和限流

- 认证失败、权限不足、资源不存在、状态冲突、参数错误和限流应有稳定且不泄密的错误分类。
- 限流响应应返回明确的重试时间信息（如 Retry-After），但不得泄露内部风控阈值。
- 普通转换失败不应直接导致账号永久封禁。
- L0 的基础转换不应被营销或会员提示阻断；只有超管明确按用户 ID 限制时才禁止。
- 限流计数必须由服务端可靠维护，不能依赖 Worker 实例内存。

## 8. API 契约与版本兼容

每个接口文档应记录：
- HTTP 方法和路径；
- 认证要求；
- 允许的身份和动作；
- 请求字段、类型、必填和校验；
- 响应字段、类型和示例（示例不得使用真实凭证）；
- 错误码及含义；
- 数据归属条件；
- 幂等和并发行为；
- 限流策略；
- 审计事件；
- 调用方及兼容性说明。

修改响应字段前，先检查所有前端、移动端、自动化任务和外部调用方。优先新增可选字段并保持旧字段兼容；删除字段或改变语义必须有版本迁移计划。

## 9. 最低 API 安全测试

- 未登录访问受保护端点；
- 客户端伪造 role/level/vip 字段；
- L0 访问 VIP 管理端点；
- 体验 VIP 到期后尝试写操作；
- 正式 VIP 到期后尝试允许/禁止的不同操作；
- 管理员 A 替换管理员 B 的资源 ID；
- 嵌套资源错配（他人的卡密、分组、批次、工单）；
- 批量请求混入越权资源；
- 重复 request_id；
- 并发激活同一卡密；
- 过期/撤销令牌访问；
- 敏感 URL 和令牌是否泄漏到响应、日志或错误信息；
- 限流与 Retry-After；
- 旧版前端对响应字段的兼容性。

测试必须记录实际请求、预期、实际响应和证据；不得只用代码阅读代替运行测试。
