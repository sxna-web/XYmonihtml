# 星跃 APP｜离线可用性、内容留存与用户体验连续性设计

- 文档版本：SJ-APP-UX-OFFLINE-001 V1.0
- 日期：2026-11-28
- 状态：用户已明确的产品要求 + 待实施设计；不是已上线功能证明
- 适用客户端：星跃 APP（当前审计基线 6.00.48；建议下一大版本 6.00.50，版本号需出包前核准）
- 关联：APP 6.00.48 客户端协议审计报告、V2.5 功能基线、APP 多卡密/分组业务规则

## 0. 用户新增的最高优先级要求

1. 用户体验必须作为核心验收标准，不只检查接口能否调用，还要检查用户是否看得懂、等得起、失败后能否恢复、内容是否会丢。
2. APP 可能受网络、访问工具、目标服务可达性、平台限制等影响，不保证任何时候都能访问服务端；不得把在线访问作为打开 APP、查看已保存内容或继续使用本地功能的前提。
3. APP 中用户已经取得或编辑的有效内容必须有本地留存和明确的恢复机制；网络恢复后可继续同步，不能因短暂无法访问而清空、覆盖或丢失。
4. 每次 APP 重大操作、同步状态和必要业务变更应留下可追溯记录；开发方也必须在仓库保留客户端源码审计、接口契约、数据结构、测试结果和下一步接手记录，后续不依赖临时访问 APK/APP 才能继续开发。
5. 不得把“本地记录”误称为服务器已成功保存；界面必须区分本机已保存、等待同步、服务器已确认、同步冲突和同步失败。

## 1. 产品体验目标

- **先可用，再联网**：APP 冷启动优先展示本地已保存的首页、订阅/分组/节点和最近状态；后台再做轻量联网刷新。
- **不因网络故障清空内容**：网络超时、DNS 失败、服务端 429/5xx、访问工具受限、服务不可达，都不能把已有节点和用户记录当作空数据覆盖。
- **状态可解释**：用户能知道内容来自本地缓存还是服务端最新结果，最近一次成功同步时间，当前是否有待同步操作。
- **操作可恢复**：用户关闭 APP、系统杀进程、手机重启后，草稿和本地内容仍能恢复。
- **少打扰**：网络失败不反复弹窗、不无限重试、不连续震动；错误提示提供可执行的下一步。
- **保护数据**：凭证与订阅敏感内容加密保存；日志不记录明文卡密、Token、完整订阅 URL。

## 2. 本地数据留存范围

### 2.1 必须持久化

| 内容 | 本地保存 | 联网后处理 | 失败时行为 |
|---|---|---|---|
| 用户手动创建/编辑的分组 | 是 | 按明确同步规则上传 | 保留本地版本 |
| 已成功解析的节点及来源关系 | 是 | 后台增量刷新 | 继续显示上次可用内容 |
| 已取得的免费/卡密授权摘要 | 是 | 校验授权状态/期限 | 显示最近确认状态，不伪造仍有效 |
| 多张卡密 entitlement 的安全凭证 | 加密保存 | 逐条核验、刷新 | 不覆盖其他卡密记录 |
| 最近使用、收藏、排序和界面偏好 | 是 | 必要时跨设备同步 | 本地继续使用 |
| 未提交表单和编辑草稿 | 自动保存 | 用户确认后提交 | 下次启动恢复草稿 |
| 转换输入与最近结果 | 按用户保存策略 | 按云端归档规则上传 | 本地可查看/复制，明确保存状态 |
| 同步任务队列 | 是 | 网络恢复后有限续传 | 保留任务及失败原因 |
| 操作记录/最近活动 | 是 | 可用时同步审计摘要 | 本地可查，标明本机记录 |

不得无限保存敏感原始订阅内容；保存期限、加密方式、用户删除机制必须与隐私政策和现有数据留存规则一致。

### 2.2 本地记录状态字段

所有需要同步的对象至少有：
- 本地稳定 ID（UUID）；
- 远端 ID（若已分配）；
- 对象类型、所属用户/管理员 ID；
- 本地版本号与服务端版本号/ETag；
- 创建/修改时间；
- 本地状态：local_only / pending_sync / synced / conflict / failed；
- 最近一次同步时间和错误分类；
- 删除标记（tombstone），不直接物理清除待同步对象；
- 数据格式版本，用于未来迁移。

敏感字段单独加密；审计记录只保存对象 ID、动作、时间、结果和脱敏摘要。

## 3. 离线启动和页面行为

### 3.1 启动

1. 先打开本地 Room 数据库，展示可用内容。
2. 首页明确显示“离线可用”或“正在更新”，不显示空白加载页阻断用户。
3. 网络检查在后台进行，使用短超时；不阻塞主线程。
4. 只有首次安装且没有任何本地数据时，才显示需要联网初始化的引导页。
5. 若本地数据库升级失败，保留原数据库备份/恢复点，不自动清空重建。

### 3.2 状态提示文案

- 本机已保存：内容已保存在这台设备。
- 等待同步：本机已保存，网络恢复后继续同步。
- 已同步：服务器已确认保存。
- 内容较旧：显示最近成功同步时间，可手动刷新。
- 同步冲突：本机和服务器都有新修改，请选择保留哪一版或查看差异。
- 服务暂不可用：不影响查看本机已保存内容。
- 授权状态待核验：显示最后一次服务端确认时间和到期时间；不能把缓存授权状态伪装成当前有效。

### 3.3 不能这样做

- 请求失败后返回空列表并覆盖本地节点。
- 将 HTTP 429、503、超时等当成“用户没有分组/没有节点”。
- APP 启动必须等待远端授权/节点接口返回。
- 在没有明确提示的情况下删除本地旧数据。
- 自动无限重试激活、写入、删除或支付相关操作。
- 用弹窗遮挡核心内容，或每次打开 APP 都重复提醒同一网络故障。

## 4. 同步与网络访问策略

### 4.1 请求分级

- GET/HEAD：可做有限重试；网络错误、超时、502/503/504最多一次短间隔重试，尊重 Retry-After。
- POST/PUT/PATCH/DELETE：默认不自动重放；只有服务端明确支持幂等键和安全重放的特定操作，才允许一次受控重试。
- 429：不立即重试；展示服务端 Retry-After 和倒计时/稍后重试入口。
- 401/403：区分登录失效、授权到期和权限不足，不反复请求。
- 404：只有接口契约确认资源不存在时才作为删除/缺失处理。
- 5xx/网络超时：保留现有数据，记录待重试状态。
- 无网络：停止后台请求，保持本地功能。

### 4.2 同步流程

1. 拉取服务端变更，验证响应 schema、版本、用户/管理员归属、完整性和数量上限。
2. 先写入临时 staging 数据。
3. 全部验证通过后在 Room transaction 中原子合并。
4. 响应为空、截断、字段不兼容或部分解析失败时，不提交覆盖。
5. 本地修改进入持久化队列，带唯一 operation ID、对象版本和幂等键。
6. 网络恢复后按依赖顺序提交；单项失败不阻断无关只读功能。
7. 服务端确认后标记 synced 并保存远端版本。
8. 冲突不静默覆盖；按字段级策略合并或提示用户选择。

### 4.3 离线队列限制

可以排队：用户草稿、可幂等的偏好/收藏/备注更新、明确支持幂等的分组编辑。

不得在离线状态伪装成功：卡密激活、支付确认、账号安全设置、权限变更、管理员分享发布、不可逆删除。此类操作应显示“需要联网确认”，提交结果不确定时提供状态查询，不鼓励重复点击。

## 5. 星跃 APP 多卡密与分组用户体验

- 同一用户可同时保留同一管理员多张有效卡密，各卡密的卡密分组分别呈现。
- 同一管理员免费分组只呈现一次，不因多卡密重复。
- 不同管理员的数据严格隔离，界面按管理员分区或清晰标识来源。
- 同名分组不能混淆：展示管理员/卡密来源和必要的序号；同一远端 group ID 去重，不同管理员的同名组不能错误合并。
- 空分组卡密仍显示授权状态，不显示“同步失败”。
- 卡密失效、VIP 到期或网络不可达时，明确显示最后确认状态；不擅自把本地缓存授权当作可继续在线使用的有效授权。
- 分组被禁用/删除/改类型后，按服务端 generation/tombstone 增量同步；APP 收到 tombstone 后先标记待清理，按已确认规则 24 小时内完成本地清理并回传 cleanup ACK。
- 在完整 tombstone/ACK 闭环完成前，不对已映射分组开放物理删除。

## 6. 用户内容保护与恢复

- 草稿自动保存：编辑时节流写入本地数据库，退出页面/切后台时再做一次落盘。
- 崩溃恢复：重启后提示恢复未提交草稿，不自动提交。
- 本地数据导出：提供用户可理解的备份/导出入口；默认加密导出，导入前预览，禁止覆盖现有数据而无确认。
- 清理功能：区分清理缓存、删除本地副本、删除云端记录；每种动作说明影响范围。
- 卸载/换机提示：明确哪些内容仅在本机，建议用户先完成可用的加密备份/云端同步。
- 敏感凭证：使用 Android Keystore 保护密钥；不把 Token/卡密明文写入普通日志、导出包或崩溃报告。
- 数据库迁移：Room migration 必须可回滚或有备份策略；严禁 destructive migration。

## 7. 操作历史与开发连续性记录

### 7.1 APP 内“最近活动/同步记录”

至少记录：
- 用户主动激活/刷新/编辑/导入/导出/删除等动作；
- 对象 ID、所属管理员/卡密 ID（脱敏展示）；
- 操作开始和完成时间；
- 结果：本地保存、待同步、服务器确认、失败、冲突；
- 失败分类和建议动作；
- 服务端 request_id/trace_id（若有）；
- 数据版本/同步游标。

用户可查看最近记录、重试安全操作、复制诊断摘要。诊断摘要不得包含卡密、完整 Token、完整订阅 URL、密钥或个人敏感数据。

### 7.2 开发方必须在仓库保存的 APP 资料

由于 APP/访问工具可能暂时不可访问，后续每次审计必须把可复核的事实写入 GitHub 文档：
- 原始 APK/源码 ZIP 文件名、SHA-256、大小、获取日期；
- package/versionName/versionCode/minSdk/targetSdk/compileSdk；
- API endpoint、HTTP method、request/response schema、鉴权方式；
- 关键源码文件路径及关键类/方法职责；
- Room entity/DAO/database version/migration；
- 关键 UI 页面、入口、用户操作路径；
- 权限、缓存、离线行为、网络超时/重试策略；
- 第三方依赖、许可证和上游来源；
- 已实现/部分实现/未实现/风险/待确认矩阵；
- 测试命令、实际结果、日志链接和提交 SHA；
- 当前阻断、下一批实施顺序和回滚说明。

严禁记录密钥、真实卡密、Token、完整订阅 URL、用户隐私和未脱敏日志。

### 7.3 每次 APP 审计交付

必须同时更新：
1. 一份按版本命名的 APP 静态审计报告；
2. 一份稳定的 APP 接口/数据结构基准文档（新发现追加版本，不覆盖历史）；
3. 总进度 ledger；
4. 下一会话接手卡；
5. 如有代码变更，附可复现测试和结果。

即使以后暂时无法重新访问 APP，也必须能仅凭以上资料继续设计接口、Room migration、UI 和测试；重新获得源码时再核对是否有版本漂移。

## 9. 现有 6.00.48 审计发现与落地差距

- 现有客户端只保存单个 token/expiry/admin ID，需升级为多 entitlement 持久化模型。
- 现有客户端没有分组读取 API；需要补充服务端组合接口和客户端解析。
- 现有 Room ProxyGroup 缺少远端 group/admin/card/generation/tombstone 元数据。
- 现有 links() 在 HTTP 错误时返回空列表，需区分空结果与失败。
- 现有请求 10 秒连接、15 秒读取超时，无统一有限重试和 429/503 分类。
- 现有激活按钮无并发点击保护。
- 现有启动固定刷新五个内置分组，Slot 02–05 仍是占位符；应先明确这些固定组与用户动态分组的兼容迁移，不能直接删除用户现有数据。
- 现有 APP 更新检查 current=60047 与 APK versionCode 355 的关系待确认。
- 本轮为设计和需求落档，不代表 APP 已具备上述能力。

## 10. 实施顺序（优先用户体验与数据安全）

1. 建立 APP 版本资料基准、Room schema inventory 和可复核接手卡。
2. 先修复错误处理：links 空结果/网络失败分离、统一超时、有限重试、重复激活点击保护、保留旧缓存。
3. 实现 Room 持久化与无破坏迁移：草稿、最近活动、同步状态、缓存时间。
4. 实现多 entitlement 模型与免费分组去重。
5. 冻结服务端/客户端分组响应契约，完成多管理员隔离和多卡密组合。
6. 实现分组增量同步、generation/tombstone、24 小时清理与 cleanup ACK。
7. 实现冲突处理、导出/恢复、隐私与诊断摘要。
8. 完成离线、弱网、重启、并发、数据迁移和真实设备验收。
9. 生成 APP 正式候选包与 Worker/HTML 对接版本；只有在测试完成且获用户批准后发布。

## 11. 验收红线

- 网络不可用不能导致已有内容丢失。
- 服务器失败不能伪装成空数据。
- 本地已保存与服务器已确认必须区分。
- 不得静默覆盖用户修改或不同管理员数据。
- 不得用本地缓存绕过服务器授权、会员有效期和敏感操作鉴权。
- 不得为离线体验而允许离线激活、支付确认、权限提升或不可逆管理操作。
- 没有真实设备测试，不得声称离线/弱网体验已验收。
