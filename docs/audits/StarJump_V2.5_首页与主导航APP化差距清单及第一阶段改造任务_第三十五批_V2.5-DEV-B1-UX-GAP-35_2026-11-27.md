## 3. 主要差距与决定

### P0：先解决导航语义不统一

现有已登录底部导航是“首页、节点、转换、卡密、我的”；访客底部导航是“转换、默认分组、我的批次、注册”，只有四项。桌面菜单则没有同一套一级导航定义，且“APP”管理菜单与底部“卡密”入口不对应。

改造决定：
- 统一一级入口 ID 与 route mapping，桌面菜单、手机底部导航、首页快捷入口全部引用同一份导航配置。
- 已登录用户采用五个一级入口：**首页、转换、节点、APP、我的**。
- “APP”入口进入 APP 工作台，再按服务端确认的权限显示概览、卡密、用户、设备、版本、授权分享等模块；普通注册用户与非有效 VIP 不得出现可执行的受限操作。
- “我的”集中账号资料、VIP/权益、分享入口（按权限）、统计入口（按权限）、安全设置、帮助与诊断。
- 访客继续提供基础转换、本人批次、默认分组查看/复制和注册入口；采用明确的访客导航模式，不显示伪装成完整会员后台的入口。视觉上仍保持同一导航框架与一致位置，不为凑满五项塞入无意义功能。
- 所有导航仅控制可见性；Worker 必须重新做身份、角色、资源归属和操作授权。

### P0：首页必须从“概览页”变成工作台

首页首屏按任务优先级组织，而不是把全部统计卡片堆上去：

1. 身份区：当前账号、角色、会员状态；访客明确显示访客状态。
2. 系统状态区：系统版本、Worker 连接状态、最近数据更新时间。没有真实 API 时显示“演示/未连接”，绝不伪造在线状态。
3. 高频操作区：开始转换、管理订阅、查看节点、APP 管理（按权限展示）。
4. 待处理区：同步失败、待处理授权、异常任务、需要确认的事项；只展示真实接口返回的数据。
5. 核心概览：按角色显示少量关键数据；访客不显示无权查看的数据。
6. 最近工作：最近转换批次、最近访问页面、最近操作；列表支持一键回到原工作上下文。

首页第一屏最多突出一个主操作，其他快捷入口采用轻量卡片；不得让访客看到点击后必然失败的 VIP 功能按钮。

### P1：菜单需要更容易找到

- 侧滑菜单顶部增加菜单搜索，搜索结果只列出当前身份可访问的菜单。
- 按业务域分组：工作台、转换、订阅与节点、分享、APP 管理、统计、系统管理。
- 当前业务域自动展开，其他分组默认折叠；保留用户手动展开状态。
- 支持收藏常用入口和最近访问，但收藏不能绕过权限。
- 手机菜单项触控区域至少 44px；关闭按钮明确；点击菜单后自动关闭抽屉。
- 菜单名称使用用户能理解的中文，避免“后台 VIP”等不清晰标签；技术诊断入口放在系统管理/我的的适当位置，不挤占一级导航。

### P1：状态保留与返回行为

- 一级入口切换后保留各自的子页面、筛选、搜索条件和滚动位置。
- 打开详情/抽屉后返回先关闭浮层，再回列表；列表状态恢复。
- hash 路由变化同步更新底部导航和侧栏当前项，避免两个导航显示不同页面。
- 刷新或会话重新登录后，恢复安全的页面位置与非敏感草稿；不得把密码、卡密、Token、订阅 URL 存入普通本地存储。
- 页面切换时避免重复渲染导致表单丢失；网络错误不应清空用户输入。

### P1：响应式细节

- 手机底部导航需避让 Android 手势安全区与键盘；键盘弹起时可隐藏或调整导航，不能遮挡提交按钮。
- 当前页标题与主操作保持可见；顶部搜索在手机端可通过独立搜索入口唤起，不直接占据顶栏宽度。
- 主内容底部增加与 bottom-nav 等高的安全留白，避免最后一条记录被遮挡。
- 访客、普通注册用户、有效 VIP、过期 VIP、体验 VIP、超管分别测试入口与权益说明。
- 桌面保留左侧分组菜单和可折叠能力；宽屏可显示右侧上下文面板，窄屏自动单列。

## 6. 明确不做的事情

- 不把全部桌面菜单塞进底部导航。
- 不把“APP 管理”简单等同于“卡密”。
- 不让访客看到受限按钮再靠点击时报错。
- 不用本地模拟数字冒充 Worker/D1 实时数据。
- 不为了视觉效果加入无意义动画、过多彩色卡片或占屏悬浮按钮。
- 不在本批修改正式 HTML、Worker、D1 或部署环境。
- 不以隐藏前端入口代替服务端权限校验。
