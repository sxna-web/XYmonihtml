# 星跃管理平台 V2.5：APP 化网页交互与移动端优先体验规范

- 批次：第三十四批
- 版本标识：`V2.5-DEV-B1-UX-34`
- 日期：2026-11-27
- 状态：交互设计规范；未修改 HTML/Worker 运行代码；不可部署
- 依据：`星跃模拟后台 1.4.61.html`（blob `d046f71caa5af96b0c0978013771cb0a8f101739`）、HTML→Worker→D1 功能映射报告、第三十三批数据库迁移设计
- 目标：网页端操作体验接近成熟手机 APP，同时在桌面端保持高效管理能力

## 1. 产品体验原则

网页端不是把桌面后台缩小到手机屏幕，也不是单纯增加圆角和动画。目标是让用户像使用 APP 一样完成主要任务：

1. **移动端优先**：先保证手机单手可操作，再扩展到平板和电脑。
2. **任务优先**：用户进入页面后，第一眼看到当前状态和最重要的下一步操作。
3. **少层级**：常用功能最多两次点击到达；复杂配置分步完成。
4. **即时反馈**：每次操作都有加载、成功、失败或待确认状态，不允许按钮无反馈。
5. **上下文连续**：切换页面、打开详情、返回列表后，尽量保留搜索条件、筛选、滚动位置和未提交草稿。
6. **安全明确**：查看、编辑、删除、执行迁移等不同风险操作必须清楚区分。
7. **一致性**：相同类型的按钮、表单、列表、弹窗、状态标签在全站使用同一套交互规则。
8. **中文优先**：用户可见界面统一简体中文，技术名词可附简短中文解释。

## 2. 对 1.4.61 HTML 的现状判断

当前 HTML 已有值得保留的移动端基础：viewport 与 safe-area 支持、900px 断点、移动侧栏抽屉、五项底部导航、卡片网格重排、表单字号调整、toast、modal/drawer、桌面侧栏折叠和右侧快捷工具栏。

但它仍是浏览器本地模拟版：页面数据通过本地存储管理，未接入真实 Worker API / D1。因此，现有界面结构只能作为交互与视觉参考，不能当成已上线的正式业务功能。

### 保留并完善

- 桌面左侧分组导航；手机侧滑主菜单。
- 手机底部主导航；中央快捷操作入口可保留，但不得遮挡正文或危险操作。
- 顶部栏保留页面标题、搜索、通知/个人入口；手机端压缩为必要控件。
- 右侧快捷工具栏仅在桌面空间充足时显示；手机改为抽屉/底部操作面板。
- 卡片、抽屉、确认弹层、toast 组件统一视觉和状态。
- 主题、侧栏、最近访问等纯外观偏好可保留本地，不默认写入 D1。

### 必须补齐

- 页面级加载骨架、空状态、错误状态、重试和离线/网络中断提示。
- 操作进行中防重复提交、幂等反馈和可追踪结果。
- 长列表分页/虚拟化、筛选条件持久化和批量操作确认。
- 表格在手机上的卡片化呈现，避免强制横向滚动。
- 表单分组、字段说明、实时校验、错误定位和草稿保护。
- 登录会话过期时保留用户输入，重新登录后可恢复未完成操作。
- 危险操作二次确认、明确影响范围和撤销/回收站策略。
- 无障碍支持：可见焦点、合理对比度、触控目标、屏幕阅读器标签与键盘操作。

## 3. 信息架构与导航

### 3.1 手机端底部主导航

建议固定五个入口，按最常用任务排序：

| 入口 | 内容 | 设计要求 |
|---|---|---|
| 首页 | 首页概览、待办、快捷操作 | 主要业务状态与常用入口 |
| 转换 | 节点转换工作区、最近批次 | 作为高频核心操作入口 |
| 节点 | 订阅源、节点、节点分组、同步记录 | 用二级页面/顶部标签切换 |
| APP | APP 概览、卡密、用户、设备、版本 | 依据用户角色展示可用功能 |
| 我的 | VIP、分享、统计入口、设置、安全、诊断 | 不把所有管理菜单挤在底部 |

底部主导航只放一级高频入口，不把所有子功能压成图标。当前页面需明确高亮；切换一级入口时保留各自上次访问的子页面状态。

### 3.2 更多功能入口

- 管理员与超管功能放入分组式侧滑菜单/“更多”页面。
- 菜单按业务域分组，支持搜索菜单名称、收藏常用入口和最近访问。
- 角色无权限的入口默认不展示；如需展示注册/VIP权益，使用独立说明卡片，不显示可点击但必然失败的假按钮。
- 菜单分组默认折叠非当前业务域，减少滚动长度。
- 任何权限最终由 Worker 服务端校验；前端菜单隐藏不构成安全边界。

### 3.3 桌面端布局

- 左侧导航可折叠，宽度稳定；中间为主工作区；右侧仅在确有价值时显示详情/快捷工具。
- 大屏可以并排显示列表与详情、表单与预览；窄屏自动改为单列。
- 不为了填满屏幕堆叠无用卡片；主内容宽度设置合理上限。
- 重要页面标题、状态和主操作保持在首屏可见。

## 4. 通用交互规范

### 4.1 页面结构

每个页面统一采用：
- 页面标题 + 一句话说明；
- 当前状态/关键指标（仅展示有业务价值的数据）；
- 一个明确的主操作；
- 搜索、筛选与排序；
- 列表/卡片内容；
- 分页或加载更多；
- 详情抽屉或详情页。

手机端不显示过多统计卡片；首屏优先呈现主任务和待处理事项。

### 4.2 列表与表格

- 桌面：表格适合字段多、对比强的管理场景。
- 手机：每行转换成信息卡，显示名称、核心状态、关键时间和一个主动作；其他动作放入“更多”菜单。
- 搜索框在滚动时可按页面需要吸顶；筛选使用底部弹层，已选条件以可移除标签展示。
- 分页必须显示当前范围和总数（若服务端可提供）；长列表采用服务端分页，不一次加载全部记录。
- 批量操作需先选择，再显示操作栏和影响数量；危险批量操作二次确认。
- 列表刷新不能无故清除筛选和滚动位置。

### 4.3 表单与分步流程

- 简单表单单页完成；复杂流程使用步骤条/分步向导。
- 每步只问完成该步骤必需的信息；提供上一步、下一步和保存草稿。
- 必填项清楚标识；输入错误在字段附近说明，不能只弹一个“操作失败”。
- 手机输入框字号至少 16px，避免浏览器自动放大；触控控件建议高度至少 44px。
- 重要提交按钮在手机端可固定于底部安全区域，但必须留出内容滚动空间。
- 退出页面前，对未保存内容提示保留/放弃。

### 4.4 反馈与状态

所有异步动作至少具备：
- idle：可操作；
- loading：正在处理，防重复提交；
- success：成功并说明结果；
- empty：暂无数据及下一步；
- error：失败原因、错误编号和重试条件；
- blocked：权限不足、环境不匹配或前置条件未满足；
- stale：数据已变化，需要刷新后重新确认。

toast 只用于简短反馈；重要结果应留在页面或操作记录中。网络中断时不能把本地按钮动画当成服务端成功。

### 4.5 弹窗、抽屉与返回

- 简单确认用小弹窗；编辑/详情用抽屉；复杂任务用独立页面。
- 手机抽屉默认全屏或近全屏，底部按钮固定，正文独立滚动。
- 返回操作遵循：先关闭最上层弹窗/抽屉，再回到上一级页面，最后才离开系统。
- 支持浏览器返回键与系统手势；避免页面刷新导致整个流程丢失。
- 弹窗打开后管理焦点，关闭后还原焦点。

## 5. 首页体验

首页是工作台，不是统计报表堆叠区。

建议首屏顺序：
1. 欢迎与当前身份/角色；
2. 系统版本与连接状态（正式环境接入后显示真实状态）；
3. 核心快捷操作：开始转换、管理订阅、查看节点、APP 管理（按权限）；
4. 待处理事项：同步失败、需要处理的授权、待确认任务；
5. 关键业务概览；
6. 最近操作/最近批次。

访客用户只展示基础转换入口、默认节点分组、本人转换记录和注册入口；同时以清楚、克制的方式说明注册/VIP 能获得的额外功能，不得让访客看到可操作的受限按钮。

首页不能展示模拟数据冒充真实数据。正式 Worker 未连接或接口不可用时，要明确标识“演示数据/暂不可用”，不能显示虚构的实时统计。

## 6. 重点业务页面的 APP 化交互

### 6.1 节点转换工作区

- 手机端采用清晰的步骤流程：选择来源/输入内容 → 选择输出格式 → 选择过滤/规则 → 预览 → 生成 → 结果与复制。
- 步骤顶部显示进度，允许返回修改前一步；非必要设置收进“高级选项”。
- 预览区支持折叠；复制、下载等主要动作放在结果页明显位置。
- 生成中显示进度/状态；网络失败可重试，但必须使用幂等键防止重复归档。
- 访客只开放基础转换能力；高级功能的权限由 Worker 再次验证。

### 6.2 订阅源与节点

- 订阅源列表使用状态卡片：启用状态、节点数量、最近同步时间、最近同步结果。
- “同步”作为明确主动作，危险操作（删除、转移归属）收进更多菜单并二次确认。
- 节点详情使用独立详情页/抽屉；收藏、备注、覆盖和分组等操作按权限呈现。
- 同步日志提供时间、结果、失败原因、影响数量和重试入口；重试必须避免旧任务覆盖新任务。
- APP 节点清理必须以 Worker generation/tombstone 与 APK cleanup acknowledgement 为准，网页端不得显示“本地已清理”假状态。

### 6.3 分享与 APP 管理

- 免费分享、卡密分享、普通网页链接三类入口视觉与说明必须区分。
- 展示授权对象、管理员身份、有效期、可访问分组和当前状态。
- 无效 VIP、过期 VIP、体验 VIP 的按钮权限按已确认业务规则展示，但 Worker 仍必须进行最终校验。
- 已激活 entitlement 与管理员 VIP 状态分别展示，避免用户误以为管理员 VIP 到期会自动撤销已激活 APP。
- 设备信息仅展示服务端可信记录；客户端自报设备 ID 不得显示成已验证设备身份。

### 6.4 数据库维护与一键升级

数据库页面是高风险管理工具，交互必须比普通页面更谨慎：

1. 首屏显示环境（production/staging/unknown）、系统版本、Worker 版本、D1 binding 检查状态和最近只读检查时间。
2. 默认只读检查；没有明确环境标签时显示“环境未知”，禁止执行。
3. 将“结构检查”“生成升级计划”“执行迁移”拆成三个不同步骤，不能保留单击即执行的旧式一键危险动作。
4. 计划页显示待迁移、已满足、冲突、阻塞和未验证对象，并展示变更影响。
5. 执行前显示环境名、plan hash、migration ID、数据风险、回滚等级；超管需输入本次计划专属确认语。
6. 执行时展示 run_id、当前步骤、已完成/总步骤和最后更新时间。
7. 失败保留现场并给出错误编号；提供重新检查，不提供绕过校验的“强制成功”按钮。
8. 只有结构 postcondition、审计记录均验证成功才显示“数据库结构已验证就绪”。
9. 诊断开关默认关闭，开启后记录脱敏日志；不得在网页展示/复制 Token、Secret、密码、完整订阅 URL 或卡密。
10. 所有操作必须遵循第三十三批 migration manifest、checksum、依赖、锁、恢复和回滚规范。

## 7. 视觉与性能规范

- 简体中文优先；字体栈兼容 Android 常见中文字体。
- 颜色只承担语义：成功、警告、错误、信息；避免每个卡片都使用高饱和底色。
- 主要按钮每个页面原则上只设一个主色主动作，次要动作使用中性样式。
- 页面动画短、克制、可关闭；尊重系统减少动态效果设置。
- 优先加载首屏，图标使用统一矢量资源；避免页面一次性加载大量图片和长列表。
- 避免横向溢出、按钮遮挡、键盘弹起时主按钮不可见。
- 适配常见 Android 手机宽度、平板、桌面和浏览器缩放。
- 支持深色/浅色主题，但状态颜色在两种主题下均有足够对比度。
- 使用安全区变量适配刘海屏、圆角屏和底部手势区域。

## 8. 体验验收矩阵

必须在真实浏览器/设备上验收，不以静态 CSS 检查代替：

| 测试场景 | 验收标准 |
|---|---|
| 手机单手操作 | 高频操作无需双手缩放或横向滚动 |
| 底部导航 | 五个一级入口可达，当前状态正确，不遮挡页面 |
| 主菜单 | 分组清楚，可搜索；打开时背景不可误触 |
| 页面返回 | 先关弹层，再返回页面；保留筛选和草稿 |
| 列表 | 手机卡片化，搜索/筛选/分页正常 |
| 表单 | 16px 输入字号，错误定位清晰，键盘不遮挡提交 |
| 网络失败 | 显示明确失败状态，不假报成功，可安全重试 |
| 重复点击 | 请求幂等，按钮 loading，不能重复创建业务数据 |
| 会话过期 | 说明需要重新登录，已填写内容可恢复 |
| 权限不足 | 按钮状态与服务端响应一致，不泄露他人数据 |
| 数据库迁移 | 检查/计划/执行分离，未知环境无法执行 |
| 横竖屏/窄屏 | 不出现主要控件被裁切或遮挡 |
| 桌面大屏 | 侧栏、主内容、可选右侧面板布局稳定 |
| 深浅色 | 文字、状态、按钮均清晰可辨 |
| 可访问性 | 键盘焦点、屏幕阅读器标签、触控目标合格 |

最低验收视口建议：360×800、390×844、430×932、768×1024、1366×768。另需至少一台真实 Android 手机浏览器验证触控、键盘、返回手势与 safe-area。

## 9. 版本实施策略

- **阶段 A：基础壳层**——导航、页面容器、主题、响应式、返回行为、通用反馈组件。
- **阶段 B：高频业务**——首页、转换工作区、订阅源、节点列表与详情。
- **阶段 C：权限与管理**——分享、APP 管理、VIP、设备和审计页面。
- **阶段 D：系统维护**——数据库检查/迁移计划/执行界面、诊断中心、版本信息。
- 每阶段先完成 HTML 交互，再按冻结 API 契约接 Worker；禁止用模拟成功状态替代真实接口。
- 先在 DEV/隔离环境验证，再进入 RC；全部功能与安全门禁通过后才可形成 V2.6.0 STABLE。
- 系统版本号与 APP versionCode/versionName 独立显示；网页系统版本不得借用 APP 版本号。
