## 1. 身份模型与适用状态

| 身份/状态 | 普通等级 | 管理身份 | 权限解释 |
|---|---|---|---|
| L0 未注册 | L0 | 无 | 匿名基础转换用户 |
| L1 已注册普通用户 | L1 | 无 | 注册用户，不因登录自动获得 VIP 管理权 |
| L2 有效 VIP 用户 | L2 | 可有 VIP 管理身份 | 有效 VIP 用户；如承担后台管理，必须同时验证管理员身份及资源归属 |
| 有效体验 VIP 管理员 | L2 | 体验 VIP | 7 天有效期内，核心 VIP 管理功能与正式 VIP 原则相同 |
| 有效正式 VIP 管理员 | L2 | 正式 VIP | 有效期内拥有完整正式 VIP 管理权限 |
| 体验 VIP 已到期 | L1/注册身份保留 | 过期体验身份 | 历史数据严格只读；不得新建、编辑、删除；复制默认禁止 |
| 正式 VIP 已到期 | L1/注册身份保留 | 过期正式身份 | 可查看和删除本人历史数据；不得新建、编辑或继续管理需有效 VIP 的分享配置 |
| 超级管理员 | 独立于 L0/L1/L2 | 超管 | 全平台最高权限；敏感操作仍须审计和必要确认 |

**关键原则：**
1. VIP 管理员不是第四种普通等级，而是 L2 用户中的管理身份。
2. “体验/正式”是 VIP 身份类型；“有效/到期”是会员状态；三者不能混为一个布尔字段。
3. Session 有效只证明登录身份，不代表拥有 VIP 权限。
4. 每个 API 必须在 Worker 服务端检查身份、会员状态、动作、资源归属、资源状态和协助会话 scope。
5. 前端隐藏按钮不构成安全门禁。
6. 超管独立于普通等级；超管敏感操作必须记录 actor、目标用户、资源、动作、前后值、时间和结果。

## 2. 动作定义

| 动作 | 含义 |
|---|---|
| 查看 | 读取列表、详情、状态、历史记录 |
| 新建 | 创建来源、节点、分组、规则、链接、卡密等 |
| 编辑 | 修改内容、配置、名称、成员、归属或状态 |
| 删除 | 删除/撤销本人有权管理的资源 |
| 复制 | 复制节点、批次、历史配置或历史数据 |
| 分享 | 创建/修改/撤销对外分享授权、分享链接或 APP 授权 |
| 管理 | 批量操作、启停、同步、导入导出、授权分配、卡密生命周期管理等；具体 API 必须拆成独立动作校验 |

说明：
- L0 不得被强制注册、弹窗、广告或会员引导阻断基础转换。
- 只有超管明确按用户 ID 限制时，才可禁止该用户基础转换。
- 普通用户只能访问自己的转换结果、节点和批次。
- 转换限流不得阻断查看/复制已生成结果（但体验 VIP 到期复制权限仍按默认严格只读处理）。
- 转换失败且未实际执行的预占额度按额度规则返还；同一幂等请求不得重复创建任务或重复计费。

资源归属硬约束：
- source 必须校验 owner/ownership、启停和审批状态；
- 节点必须校验所属 source、user_id、lifecycle/stale 状态；
- group、batch、share、card 等资源必须校验管理员 ID 和关联关系；
- 不能因用户猜到或替换资源 ID 就读取/修改他人数据；
- 任何跨用户授权必须存在明确授权记录，不能靠前端传入 owner_id 决定。

### 5.2 APP 用户授权与获取分组

| 动作 | APP 用户身份 | 规则 |
|---|---|---|
| 通过管理员身份 ID 获取免费节点分组 | APP 用户 | 允许按有效授权读取 |
| 通过 APP 用户卡密获取卡密分组 | APP 用户 | 必须使用对应管理员为该卡密配置的分组 |
| 获取免费/卡密分组的分享载体 | 系统 | 必须使用专门的星跃 APP 对接分享链接 |
| 用普通网页链接代替 APP 专用分享 | 系统 | 禁止 |
| 读取他人管理员未授权分组 | APP 用户 | 禁止 |
| 管理员删除 APP 对接分组 | 系统 | 触发撤销版本/墓碑，APK 增量同步后 24 小时本地清理 |
| 管理员将 APP 对接分组改成其他类型 | 系统 | 同样触发撤销与 24 小时本地清理 |

24 小时清理必须端到端闭环：Worker 生成 generation/tombstone → APK 拉取增量 → 本地删除 → APK 回传 cleanup acknowledgement。只在后台删记录或只在前端显示“已删除”不算完成。

### 5.3 APP 用户卡密管理

| 动作 | L0/L1 普通用户 | L2 有效 VIP 管理员 | VIP 管理员到期 | 超管 |
|---|---|---|---|---|
| 查看自己管理的卡密列表 | 不允许管理 | 允许 | 只读查看 | 全局 |
| 创建/批量生成 APP 用户卡密 | 不允许 | 允许 | 禁止 | 允许并审计 |
| 配置卡密绑定分组 | 不允许 | 允许 | 禁止 | 允许并审计 |
| 编辑/启停/删除未激活卡密 | 不允许 | 允许 | 禁止；按宽限状态自动处理 | 允许并审计 |
| 查看激活记录/事件 | 不允许 | 允许 | 只读允许 | 全局 |
| 管理他人管理员卡密 | 不允许 | 不允许 | 不允许 | 允许并审计 |

卡密隔离：
- 管理员 VIP 卡密与 APP 用户卡密是两个独立体系、独立卡池、独立权限。
- 管理员不得通过 APP 用户卡密接口管理自己的 VIP 会员卡密，反之亦然。
- 卡密明文仅在必要的创建/交付时展示；列表、日志和审计不暴露完整 code。

### 5.4 管理员到期与 APP 卡密生命周期

| 事件 | 已确认行为 |
|---|---|
| 正式 VIP 管理员到期 | 其创建且尚未激活的 APP 卡密进入 3 天宽限期 |
| 宽限期内 | 保留宽限状态；具体边界使用服务器时间 |
| 宽限期结束 | 因 owner VIP 到期而失活，记录原因 `owner_vip_expired` |
| 已激活 APP 卡密 | 不因管理员 VIP 到期自动失效，按卡密自身有效规则继续 |
| 管理员恢复有效 VIP | 只自动恢复因 `owner_vip_expired` 失活的卡密 |
| 超管手动撤销/封禁/作废 | 不因管理员续费而自动恢复 |
| 卡密自身过期 | 不因管理员续费而自动恢复 |
| 体验 VIP 管理员到期 | 未激活卡密是否有独立 3 天宽限期：**待确认** |

所有状态转换必须原子、幂等，并记录原因、时间、操作者和管理员归属。

## 8. 超级管理员动作边界

超管可管理全平台，但以下动作必须有额外安全控制：
- 查看敏感订阅 URL、原始订阅内容、完整卡密、Token；
- 修改用户身份、冻结/解冻账号、限制某用户基础转换；
- 生成/撤销/恢复会员卡密和 APP 卡密；
- 跨管理员迁移来源、分组、卡密和分享关系；
- 永久清理历史数据、清空回收站；
- 修改系统 Secret、限流、体验期限、宽限期、分享规则；
- 数据库迁移、备份恢复、生产配置变更。

要求：最小权限、二次确认、审计前后值、敏感内容脱敏、可追踪操作者。任何超管操作不得把审计失败静默吞掉后继续返回敏感明文。

## 9. Worker API 强制门禁字段

建议统一服务端授权决策输入（逻辑契约，不是现有代码字段承诺）：

| 输入维度 | 必须校验的内容 |
|---|---|
| actor | 当前真实登录主体/超管主体 |
| effective user | 协助会话实际作用用户 |
| role | L0/L1/L2 或 superadmin |
| vip_kind | trial/formal/none |
| vip_status | active/expired/revoked/unavailable |
| action | read/create/update/delete/copy/share/manage/reveal/export |
| resource_type/id | 资源类型与目标 ID |
| owner_id | 服务端查询得到的真实资源归属 |
| resource_status | enabled/archived/stale/revoked/expired 等 |
| assistance_scope | 协助会话是否允许该动作 |
| audit_requirement | 是否必须写入审计以及失败策略 |

建议统一结果：
- 允许：执行动作；
- 401：未登录/凭证无效；
- 403：身份或会员等级不足；
- 404：资源不存在或不属于当前用户（避免泄露他人资源存在性）；
- 409：资源状态冲突、版本冲突、已撤销；
- 429：限流，附 Retry-After；
- 5xx：授权依赖/数据库不可用时 fail closed，不得降级匿名或跳过检查。

**注意：** 不能直接把上述建议结果码当作当前 Worker 已有行为；实施时需保持前端兼容并在 API 契约中版本化。

## 10. 当前已确认与待确认清单

### 已确认，可直接作为验收要求
1. 普通用户只有 L0/L1/L2；超管独立最高身份。
2. VIP 管理员是 L2 管理身份，不是第四种等级。
3. 体验 VIP 7 天；有效期间核心 VIP 管理功能与正式 VIP 原则相同。
4. 体验 VIP 到期只能查看历史；不得新增、编辑、删除；复制默认严格只读禁止。
5. 正式 VIP 到期可查看和删除本人历史数据；不得编辑或新建需要有效 VIP 的管理业务数据。
6. 正式 VIP 到期三天后个人购卡入口切公共百度链接；恢复有效后恢复原入口。
7. 正式 VIP 管理员未激活 APP 卡密有 3 天宽限期；已激活卡密不因管理员到期失效。
8. 管理员恢复有效 VIP，只恢复因 owner_vip_expired 失活的卡密。
9. APP 对接分组（包括免费组）和星链接只有注册用户可使用；有效 VIP 管理员可管理，注册非 VIP/过期管理员只读。
10. APP 免费组通过管理员身份 ID 授权；卡密组通过对应 APP 卡密授权。
11. APP 免费/卡密分组必须使用专用 APP 对接分享链接，普通网页链接不能替代。
12. APP 对接分组删除或改型后，APK 本地节点 24 小时内清理，必须有服务端 tombstone/generation、客户端清理和 acknowledgement 闭环。
13. 每次成功转换均后台独立归档；相同 URL 不覆盖旧记录。
14. “仅本地保存”不参与用户端云同步，但平台仍按规则归档。
15. L0 可基础转换、查看/复制本人结果；不得强制注册。
16. 所有权限由 Worker 服务端验证；资源归属必须校验。

### 待确认，不得擅自升级为硬规则
1. L1 与 L2 高级转换功能逐项分级（单关键词、搜索、协议/地区筛选、去重、多关键词、正则、重命名、排序、多源合并、多目标/批量转换等）。
2. 体验 VIP 到期后是否允许复制历史数据（当前默认禁止）。
3. 体验 VIP 管理员创建的未激活 APP 卡密是否也有独立 3 天宽限期。
4. 同一用户是否只能领取一次体验卡，以及超管重发审批流程。
5. 普通来源、普通节点分组的 L0/L1/L2 创建、编辑、删除细则。
6. 普通用户本人转换历史的删除权限、导出权限和保留期限。
7. 正式 VIP 到期后，除 APP 对接/星链接之外的普通历史分组能否删除；不得影响专用分享配置保护。
8. 同设备多管理员 entitlement 的 UI 选择或合并方式；服务端必须支持多条授权，不能只取最新一条。
9. 免费 grant 是否永久保留及其与卡密过期的关系。
10. 分组回收站保留期限和永久清理条件。

## 11. 当前 Worker 差异与修复优先级

结合第三批只读审计报告，当前 Worker 至少存在以下已发现差异：
- APP groups/links/cards 管理写操作缺有效 VIP gate；
- filters 没有登录/VIP 服务端门禁；
- 转换接口无效 Session 可能降级匿名，guest 缺失共用 g:anonymous；
- APP Token 和转换加密使用固定默认密钥回退；
- APP status 不验证 entitlement Token；
- APP 多授权只取最新 entitlement；
- APP free grant 缺统一可验证凭证；
- ownership helper 未统一校验来源/节点生命周期状态。

本矩阵只定义目标权限，不代表这些差异已修复。正式实施前必须：
1. 先核对正式 D1 schema 与现有 Worker/API/前端调用；
2. 提交逐文件影响分析、兼容计划、数据库影响、回滚和测试计划；
3. 优先修复身份降级、固定密钥、APP Token 验证和 VIP gate；
4. 在独立测试 Worker/D1 完成越权、到期、并发、归属和回归测试；
5. 用户明确批准前，不改正式 D1、不改生产 Secret、不部署生产 Worker。
