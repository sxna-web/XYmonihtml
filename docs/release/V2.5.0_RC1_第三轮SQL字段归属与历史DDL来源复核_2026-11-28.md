### 2.1 本轮发现/纠正

1. `node_identity_aliases.updated_at` 在 UPSERT 冲突分支被写入，不能只保留早期清单中的三列。
2. `sync_tasks` 当前 Worker 不只是任务基本字段，还使用 `staged_count`、`manifest_hash`、`missing_count`、`committed_at` 等状态字段；后续 schema 核对必须覆盖完整状态生命周期。
3. `subscription_sync_state` 除租约字段外，提交收尾还写入 `last_success_at`、`last_manifest_hash`、`last_task_id`。
4. `source_approvals` 存在地址变更后的 UPSERT/重新审核分支；只看首次 INSERT 会漏掉 `reason` 等依赖。
5. `subscription_sources`、`node_records`、`node_groups`、`admin_user_scopes` 等存在 `SELECT *`。这只能证明调用端消费返回对象，不能把它当成完整表字段声明。
6. 上表属于逐表 SQL 归属证据矩阵的阶段成果，不等同于 22 张表完整 DDL、字段类型/约束矩阵，也不等同于所有动态 SQL 分支与所有 bind 参数的全量审计。

## 3. 迁移入口与数据库页安全复核

当前 Worker 只读数据库状态入口位于 `migrateRoute`（约 4020-4110 行）：

- `GET /api/super/schema-status` 只查询 `sqlite_master` 的 table 名称。
- 返回 `verification: TABLE_NAMES_ONLY`、`migration_enabled: false`，并分开报告 18 张核心历史 DDL 表与 22 张 Worker 引用表。
- `POST /api/super/migrate` 固定返回 HTTP 503、`MIGRATION_REVIEW_REQUIRED`，没有执行 CREATE/ALTER/DROP。
- 路由还要求本人登录的超级管理员 Session，拒绝 ADMIN_TOKEN 与协助会话进入数据库检查/迁移入口。
- 当前没有从此路由执行任何自动迁移的可用分支。

本结论仅覆盖当前 RC1 Worker 该路由和对应路由分发代码；不代表 Cloudflare 已部署此候选，也不代表其他历史部署版本的线上路由状态。
