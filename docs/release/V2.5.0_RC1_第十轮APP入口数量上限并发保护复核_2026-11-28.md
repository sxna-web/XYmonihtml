## 1. 发现的问题

`addAppLink` 原先先查询管理员入口数量和权限，再独立执行插入。并发请求可能同时读到尚未达到 `max_links` 的数量，随后都插入成功，突破管理员入口数量上限。管理员 APP 入口权限也可能在预读后、插入前被关闭或调整。

## 2. 修复内容

- 保留预读检查，继续提供友好的权限关闭和数量已满错误。
- 在同一个 `userBatch` 中增加最终断言：
  - 目标管理员仍存在；
  - `links_enabled` 仍为启用（无配置记录时按现有默认值 1）；
  - 当前 `app_links` 数量仍小于数据库中的 `max_links`（无配置记录时按默认值 1）。
- 插入入口和写入审计仍在同一 batch。
- 若并发请求已消耗最后一个名额，或管理员权限/数量上限已变化，断言失败并返回 409 `LINKS_LIMIT_CHANGED`，不会插入超额入口。
- 同一 helper 同时供普通管理员和超管新增入口使用，因此两种入口都获得相同的最终数量约束。

## 3. 回归测试

新增 handler 集成测试：
- 正常新增 APP 入口时，配额断言、入口 INSERT 和审计 INSERT 必须位于同一 batch。
- 模拟另一个并发请求先占用最后一个名额，当前请求应返回 409，且不得执行入口 INSERT。

静态回归新增检查：APP 入口新增必须在插入 batch 内重新检查当前权限与 max-link 数量。
