## 1. 追加发现

第十三轮已覆盖节点备注/收藏/排序、字段覆盖和分组成员关联，但普通节点详情路由还有一个入口：
- `PATCH /api/user/nodes/:id/enabled` 对订阅节点执行 `node_overrides` upsert。
- 该入口在批次外调用 `loadSubscriptionNode` 检查归属，最终 batch 之前没有再次确认来源仍属于当前用户。
- 手动节点 enabled toggle 虽然最终 UPDATE 已带 user_id，但同样缺少同批次 owner assertion，审计可能记录一个未实际生效的状态变更。

## 2. 已实施修复

- 订阅节点 enabled toggle 在 userBatch 首条语句调用 `nodeOwnerAssertStmt(db, ctx, id, "subscription")`，随后才写入 enabled override 和审计。
- 手动节点 enabled toggle 在 userBatch 中断言 `user_manual_nodes.id + user_id`，随后执行带 owner 条件的 UPDATE 和审计。
- 若归属在预读后发生变化，返回 409 `NODE_OWNERSHIP_CHANGED`，不写入 override/启停状态。
- 保留直接超管本人会话对订阅节点的既有 bypass；协助会话仍按 effective user 检查。

## 3. 回归测试

新增两项 Worker handler 集成测试：
- 订阅节点 enabled toggle 的最终 batch 必须包含 node_records + source_ownership 归属断言。
- 模拟来源归属变化时返回 409，且不执行 node_overrides INSERT。

静态回归新增检查：`userNodesRoute` 的订阅/手动节点启停路径都必须使用 `nodeOwnerAssertStmt`。
