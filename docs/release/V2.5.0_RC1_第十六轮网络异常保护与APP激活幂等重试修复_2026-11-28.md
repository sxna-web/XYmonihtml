# V2.5.0 RC1 第十六轮：网络异常保护与 APP 激活幂等重试修复

- 日期：2026-11-28
- 批次：`V2.5-DEV-B1-NETWORK-RESILIENCE-115`
- 目标：降低弱网、断网、超时、网关暂时不可用对正常用户的影响；避免网络恢复后重复提交造成重复业务操作。

## 管理后台网络处理

修改 `releases/v2.5.0-rc1/index.html` 的统一 API 请求层：

- 所有统一 API 请求增加 20 秒超时。
- GET/HEAD 读取请求最多 2 次尝试；对网络断连/超时进行一次短间隔重试，对 502/503/504 进行一次有限重试。
- POST/PUT/PATCH/DELETE 等写入请求最多 1 次，不做自动重放，避免网络恢复后重复创建、重复修改或重复删除。
- 区分离线、网络连接失败、等待超时、HTTP 429 和服务端暂时错误；429 使用 `Retry-After` 给出等待提示。
- 写入请求遇到超时/网络中断或不明确的 5xx 响应时，明确提示服务器可能已收到请求，要求先刷新核对结果，不要连续重复提交。
- APP 卡密 CSV 导出增加 20 秒超时和最多一次读取重试，并检查 HTTP 状态后再下载，避免把错误响应保存成 CSV。

## APP 卡密激活正常用户保护

修改 `backend/worker/V2.5-DEV-B1-CORE-AUTH-49/Worker.js`：

1. 限流由“所有激活请求”调整为“失败尝试”计数。成功激活不消耗失败预算；同一设备的正常多卡激活不因成功次数触发失败限流。
2. 限流 bucket 改用 `app:redeem:failed:v2:` 命名空间，避免历史版本的全请求计数残留直接阻断新版本用户。
3. 继续使用 IP 10 次、设备 5 次、15 分钟固定窗口；仍使用 Cloudflare `CF-Connecting-IP` 和 SESSION_PEPPER 派生哈希，不保存明文 IP/设备标识。
4. 限流存储故障继续 fail-closed，避免暴力猜测保护失效。
5. 新增同设备重复激活安全重放：如果第一次请求已成功提交，但响应因断网/超时丢失，同一设备再次提交同一卡密时，服务端查找该卡密对应的同设备有效授权，并返回原授权及确定性 HMAC token；不重复消费卡密、不创建第二份 entitlement、不重复写激活事件。
6. 只有同设备且仍处于 active、未到期的既有授权可以重放；其他设备不能借此取得授权，过期授权不恢复。

## 兼容性与限制

- 没有改变 APP 请求路径、卡密格式、成功响应字段结构、设备 ID 格式或 HMAC token 算法。
- 同设备重放返回原 entitlement ID 和同一确定性 token；不同设备不允许重放。
- 旧限流 bucket 不再用于新失败计数，旧数据不会直接影响新的失败计数窗口。
- 当前验证为 GitHub CI、fake/mock D1 和 HTML inline-script 语法/静态回归；尚未进行真实 Cloudflare D1 并发、弱网实机或 Android APP 6.00.48 客户端测试。
- 由于 APP 6.00.48 二进制 ZIP 尚未可读，客户端是否会自动重试、如何展示 429/503、是否会复用设备 ID仍未核实。本轮服务端兼容同设备重复激活，但不代表客户端体验已完成验收。
