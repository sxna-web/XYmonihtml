## 1. 发现

用户手动节点 PUT/DELETE 已在最终 SQL 中使用 `id + user_id`，但在最终写入前缺少统一的同批次 node-owner assertion，且未检查主节点 UPDATE/DELETE 的 changes 结果。并发删除或归属状态变化时，可能出现主记录未改变但后续逻辑仍返回成功的情况。

## 2. 修复

### PUT 更新
- 写入批次首条加入 `nodeOwnerAssertStmt(db, ctx, id, "manual")`。
- 保留最终 UPDATE 的 `WHERE id=? AND user_id=?`。
- 检查 UPDATE changes；未更新返回 409 `NODE_OWNERSHIP_CHANGED`。
- 审计继续与主记录更新在同一批次。

### DELETE 删除
- 写入批次首条加入同一手动节点归属断言。
- 保留主记录精确 owner DELETE 条件。
- 仅在主记录 DELETE 确认有变化后返回成功。
- 手动节点记录、用户元数据、分组成员清理和审计继续同批次执行。

## 3. 测试与静态回归

新增两项 handler 测试：
- 手动节点更新必须包含 owner assertion、最终 owner predicate、写入结果检查和审计。
- 手动节点删除必须包含 owner assertion，并在同批次清理 metadata、group members 和审计。

静态回归要求 PUT/DELETE 两条路径都包含 owner assertion 和 changes 检查。

最终 Worker handler integration tests：55/55 passed；authorization adapter tests：12/12 passed。Worker bundle、Cron/static regression、isolated SQLite verifier、artifact upload 全通过。
