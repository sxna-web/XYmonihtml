## 1. 本轮审计发现

用户态订阅源启停 PATCH 和编辑 PUT 已有来源归属断言、最终 SQL owner predicate 及同批次审计，但没有检查 batch 中主 UPDATE 是否真正修改了记录。仅有 owner assertion 并不足以保证接口只在最终写入成功后才返回成功。

## 2. 修复内容

### PATCH /api/user/sources/:id/enabled
- 保留来源归属 fence 和启用时的审批状态 fence。
- 根据实际加入的断言语句计算最终 UPDATE 的 batch 索引。
- 检查 UPDATE 的 `meta.changes`；没有修改时返回 409 `SOURCE_STATE_CHANGED`。
- 审计语句继续与 UPDATE 位于同一批次。

### PUT /api/user/sources/:id
- 保留归属 fence、最终 SQL owner predicate、地址变更重新审核/停用逻辑。
- 按是否存在 owner guard 定位最终 UPDATE 结果。
- 检查 UPDATE 的 `meta.changes`；无写入时返回 409，不再报告成功。
- URL 变更审批状态、停用、审计仍保持在同一批次。
