## 1. 发现的问题

超管 `/api/super/releases` 与 `/api/super/announcements` 的写入路径仍有直接 `.run()`：
- 发布记录创建/删除没有同批次审计。
- 公告创建/启停/删除没有同批次审计。
- 公告启停先读记录再独立 UPDATE；删除直接 DELETE，缺少同批次存在性断言。
- 操作成功与审计写入无法保持同一批次，失败时可能出现缺少审计记录的业务变更。

## 2. 已实施修复

### 2.1 APP/平台版本发布记录
- 创建：版本记录 INSERT 与 `release.create` 审计同批次。
- 删除：先读取快照，同批次断言记录存在、DELETE、写 `release.delete` 审计；未命中返回 409。

### 2.2 公告管理
- 创建：公告 INSERT 与 `announcement.create` 审计同批次。
- 启停：读取 active/title/scope 快照，同批次断言公告存在、UPDATE active、写 before/after 审计。
- 删除：读取公告快照，同批次断言存在、DELETE、写 `announcement.delete` 审计。
- 删除/更新未命中时返回 409 或 404，不再默默返回成功。

## 3. 回归测试

新增 Worker handler 集成测试：
- 超管创建发布记录：INSERT + audit 同批次。
- 超管删除发布记录：存在性断言 + DELETE + audit 同批次。
- 超管创建公告：INSERT + audit 同批次。
- 超管启停公告：存在性断言 + UPDATE + audit 同批次。
- 超管删除公告：存在性断言 + DELETE + audit 同批次。

静态回归要求 `superReleasesRoute` 不再包含直接 `.run()`，并要求至少五类写操作均使用 batch 和 audit。
