## 1. 发现的问题

### 1.1 节点备注/收藏/排序元数据

`userMetadataRoute` 先通过 `loadAnyNode` 读取节点并确认归属，再写入 `node_user_metadata`。若订阅来源在检查后转移给其他管理员，旧请求仍可能为已失去归属的节点创建或更新个人元数据。

### 1.2 节点字段覆盖

`userOverridesRoute` 的 PUT/DELETE 先通过 `loadSubscriptionNode` 验证来源归属，再写入/删除 `node_overrides`。最终批次此前没有重新检查节点仍归当前用户所有。

### 1.3 节点分组成员关联

节点分组成员 POST 在批次外检查 group 与 node 归属，但最终 INSERT 没有在同一批次重新验证两者；并发删除/转移后可能插入过期成员关联。分组更新/删除也需要在批次内确认 group 仍属于当前用户。

## 2. 已实施修复

### 2.1 新增统一 nodeOwnerAssertStmt

统一处理：
- 手动节点：最终断言 `user_manual_nodes.id + user_id`。
- 订阅节点：最终断言 `node_records` 与 `source_ownership` 仍匹配当前 effective user。
- 直接超管本人会话：保留既有对订阅节点的超管 bypass，但仍确认 node_records 记录存在。
- 协助会话不会使用超管 bypass。

### 2.2 节点元数据与覆盖写入

- `userMetadataRoute` 将 node owner assertion 与元数据 upsert、审计放入同一个 userBatch。
- `userOverridesRoute` 的 PUT/DELETE 均在业务写入前同批次重新断言订阅节点归属。
- 若归属断言失败，返回 409 `NODE_OWNERSHIP_CHANGED`，不执行元数据/覆盖写入。

### 2.3 节点分组及成员

- 分组 PUT/DELETE 同批次断言 group 仍归当前用户。
- 分组删除顺序调整为：先删成员关联，再删分组主记录，最后审计；避免父记录先删后子关联处理失败。
- 成员 POST 同批次断言 group 归属与 node 归属，再插入成员关联和审计。
- 并发变更导致断言失败时返回 409 `GROUP_MEMBER_STATE_CHANGED`。
- 成员 DELETE 同批次断言 group 仍归当前用户，最终 DELETE 保留 user_id + group_id 条件。

## 3. 回归测试

新增 Worker handler 集成测试：
- 节点分组成员新增同时包含 group owner 与 manual node owner assertion。
- 模拟节点归属变化时拒绝成员新增且不执行 INSERT。
- 手动节点元数据写入包含最终 user_manual_nodes 归属断言。
- 订阅节点字段覆盖写入包含 node_records + source_ownership 断言。
- 模拟订阅来源归属变化时覆盖更新返回 409，且不执行 INSERT。

静态回归增加 nodeOwnerAssertStmt 覆盖检查，确保 manual/subscription 两种节点均有 owner guard，并检查覆盖、元数据和分组成员路径调用该 guard。
