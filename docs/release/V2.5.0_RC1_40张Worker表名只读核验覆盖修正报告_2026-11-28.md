# V2.5.0 RC1｜40 张 Worker 表名只读核验覆盖修正报告

- 日期：2026-11-28
- 分支：`release/v2.5.0-rc1-converge`
- 状态：代码已修改，等待本轮 CI 回归；只读检查，不含 D1 结构迁移
- 安全边界：未连接 Cloudflare、未读取生产 D1、未读取 Secrets、未执行 SQL、未部署

## 1. 本轮发现

原 RC1 的 `/api/super/schema-status` 只检查 18 张核心表名，但静态 Worker 依赖清单记录了 40 张不同表：
- 18 张有历史源码 CREATE TABLE 证据（A 类）
- 22 张只有 Worker SQL 字段引用证据（B 类）

旧接口仅返回 18 张表的 `required_tables_present`。因此即使这 18 张都存在，后台也可能给出过于乐观的状态，无法说明另外 22 张 Worker SQL 引用表是否存在。

## 2. 修正内容

### Worker

- 保留原 18 张核心表检查，兼容既有 `required_tables_present` / `have` / `missing` 字段。
- 新增 22 张 Worker SQL 引用表的独立只读检查。
- 新增 `worker_referenced_tables_present`、`worker_referenced_have`、`worker_referenced_missing`、`worker_referenced_table_count`。
- 新增 `all_worker_tables_present` 与 `total_checked_table_count`，总计覆盖 40 张表名。
- 查询仍只读 `sqlite_master`；没有 DDL、ALTER、DROP、自动补表或数据修改。
- `verification` 仍明确为 `TABLE_NAMES_ONLY`，`migration_enabled` 仍为 false。

### 后台 HTML

- 数据库检查提示分开显示 18 张核心表与 22 张其他 Worker SQL 引用表。
- 显示各自存在数、缺失数及 40 张表总状态。
- 明确提示只核对表名，不代表字段、索引、约束或数据完整性通过。
- 仍不调用迁移 API，不触发任何数据库写入。

### 自动回归脚本

- 要求 Worker 18 张核心表列表与 A 类清单完全一致。
- 要求 22 张引用表列表与 B 类清单完全一致。
- 要求两组无重叠且合计 40 张。
- 要求 HTML 消费新增只读状态字段。
- 继续检查 SQL 引用覆盖、迁移路由 fail-closed 与只读边界。

## 3. 40 张表名分类

A 类（18 张历史 CREATE TABLE 证据）：
`admin_app_perms`、`admin_share_codes`、`admin_vip_activations`、`admin_vip_cards`、`announcements`、`app_card_events`、`app_cards`、`app_entitlements`、`app_free_grants`、`app_group_members`、`app_group_sources`、`app_groups`、`app_links`、`convert_links`、`download_links`、`node_lifecycle`、`rate_limits`、`releases`。

B 类（22 张 Worker SQL 字段引用证据）：
`app_users`、`user_sessions`、`admin_user_scopes`、`subscription_sources`、`source_ownership`、`source_approvals`、`subscription_sync_state`、`sync_tasks`、`sync_task_stage`、`sync_task_manifests`、`node_records`、`node_groups`、`node_group_members`、`node_overrides`、`node_user_metadata`、`node_identity_aliases`、`user_manual_nodes`、`source_quota`、`app_settings`、`admin_audit`、`admin_audit_events`、`node_sync_logs`。

## 4. 仍然不能得出的结论

- 表名存在不代表字段完整、类型/default/CHECK/UNIQUE/FK/索引一致。
- A 类是历史源码 CREATE TABLE 证据，不证明生产 D1 当前结构。
- B 类是 SQL 字段引用线索，不是完整建表定义；不得据此生成猜测型 CREATE TABLE。
- 本轮不生成生产迁移 SQL，不打开旧 `/api/super/migrate`。
- 仍需获得经用户明确授权的目标 D1 只读结构快照，才能逐表逐列比较；生产写入或迁移还需单独审批、备份和回滚验证。
