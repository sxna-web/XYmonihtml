## 1. 发现的问题

### 1.1 超管新增授权

新增管理员 scope 前会先检查目标用户存在，再独立执行授权 batch。若目标用户在检查后被删除/停用，可能在授权操作中产生不一致或依赖 FK 失败。

### 1.2 超管撤销授权

撤销授权原先先读取 scope，再批量更新授权与相关会话，但没有在同一批次重新确认授权仍有效；重复撤销也没有明确的幂等返回。

### 1.3 转换链接分组批量改名

转换链接分组改名原先直接 UPDATE 全组记录，再独立写审计。审计失败时，分组已改名但缺少审计；并发请求可能在预读数量后将原分组改空，仍产生不准确的结果。

## 2. 已实施修复

- **新增授权**：同一 userBatch 中先断言目标 app_users 记录仍存在，再处理已过期授权、插入新授权和写审计。目标用户状态变化返回 409 `TARGET_USER_CHANGED`；唯一约束并发冲突仍返回 409 `SCOPE_ALREADY_ACTIVE`。
- **撤销授权**：已撤销记录返回幂等成功；未撤销记录在同批次断言仍有效、更新 scope、撤销相关会话并写审计。并发状态变化返回 409。
- **转换分组改名**：先读取原分组数量；若为 0 直接返回 0。数量大于 0 时，在同一 D1 batch 内断言原分组仍存在、批量 UPDATE、写入改名前后及影响条数审计。并发改空返回 409。
