## 本次已核实的事实

1. PR #1（`repair/v2.5-batch1-auth-vip-app`）与当前 main 已分叉：PR 领先 18、落后 495；共同基点为 `da5c76d93014a673027430e2fd67ac6f75ec42eb`。禁止直接合并或直接部署 PR 文件。
2. PR #1 最近一次冒烟 Run `46091733229` 成功；只覆盖 Worker/HTML 语法和静态断言，不覆盖真实 D1、Cloudflare runtime、Secrets 或 APK 联调。
3. 当前 main 的 Batch49 Worker 位于 `backend/worker/V2.5-DEV-B1-CORE-AUTH-49/Worker.js`，通过相对 import 使用 `worker-auth-adapter.mjs`；该 adapter 又依赖 Batch47 `authorization.mjs`。Batch49 README 明确标注 NOT DEPLOYABLE。若最终仍交付单 Worker 文件，必须经打包生成自包含 Worker，并对打包产物重新运行语法和行为测试。
4. Batch49 包含有效 VIP 管理写门禁、最终 SQL owner predicate 和正式 VIP 到期历史删除截止条件；PR #1 release Worker 没有这些 Batch49 owner predicate，不能用 PR Worker 覆盖 main。
5. 当前 main Batch49 Worker 的 Cron 入口仍在读取同步来源后执行 `if (!sources.length) return;`，导致无同步来源时跳过 VIP 卡密、节点生命周期和 APP entitlement 维护。PR #1 中有修复此问题的代码，但必须把修复移植到保留 Batch49 权限加固的候选 Worker。
6. PR #1 的 Worker 还包含无效 Bearer 不降级匿名、SESSION_PEPPER 强制长度、APP_HMAC_SECRET 兼容、APP status Token 校验、多 entitlement 读取等安全变更；需要逐项移植并验证，不能以“PR CI 成功”替代与 Batch49 的合并验证。
7. main 中用于 Cloudflare 后台页面的源 HTML 是 `原始StarJump_V1点0_Final-zip-26-11-25-14:56/index.html`；PR #1 的 HTML 是另一个版本。需要逐项确认 API base 和页面调用契约后选择，不得仅凭文件名认定兼容。
8. Batch85 离线审查 Run `46091231949` 失败：`test_dimension_type_scope_prevents_alias_merge` 复用相同 owner-scoped event_id，触发 event tuple immutability 冲突。该失败属于离线模型测试，不代表 D1/Worker 已集成；修正测试语义前不能将 Batch85 CI 标记通过。
