## 1. 本轮发现

订阅节点启停和手动节点启停在原有归属断言之外，还需要检查最终写入结果，不能在主记录未更新时仍返回成功。

更重要的是，测试暴露出一个实际路由缺口：手动节点的 PATCH `/api/user/nodes/manual/:id/enabled` 请求会先进入手动节点分支，但该分支原先只实现 POST/PUT/DELETE，未实现 PATCH enabled；后续通用分支无法正确处理该路径，因此返回 405。该功能此前不能视为已可用。

## 2. 已实施修复

### 订阅节点启停
- 保留同批次 `nodeOwnerAssertStmt(..., "subscription")`。
- 对 enabled override upsert 检查 batch result changes。
- 无实际写入时返回 409 `NODE_OWNERSHIP_CHANGED`，不报告成功。

### 手动节点启停
- 在手动节点分支内补齐 PATCH enabled 路由。
- 解析并校验 enabled 值。
- 同批次重查节点归属、执行 `UPDATE ... WHERE id = ? AND user_id = ?`、写入审计。
- 检查 UPDATE changes；归属变化或写入未生效时返回 409。
