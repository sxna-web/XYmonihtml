- 范围：APP 分组/入口链接读取授权、卡密状态最终校验、令牌数量边界；不改变 APP 客户端二进制。
- 设计依据：Batch118 APP 6.00.48 客户端协议审计、Batch119 离线可用性/内容留存设计、Batch120 卡密映射 JOIN mock 对齐。

## 一、本轮修复

1. `/api/app/groups` 使用重复 query 参数 `token=` 收集多卡密 token；每条 entitlement 必须与其自己的 token 匹配，匹配成功的 entitlement 才参与卡密分组组合。兼容旧客户端只发送单 token 的方式。
2. 对 token 数量设置明确上限 100；先检查上限，不在检查前截断，避免超量输入被静默接受。
3. APP 分组 entitlement 查询同时 JOIN `app_cards`，重新核验卡密归属、used 状态、手动禁用和卡密到期；即使 entitlement 状态暂时仍为 active，已禁用/已到期卡密也不会继续读取分组。
4. `/api/app/links` 同样支持多 token 与多 entitlement，只返回至少有一个匹配 token 的 entitlement 所属管理员链接；链接查询同时重新核验卡密状态/手动禁用/到期，避免失效卡密继续授权。
5. 测试 mock 对映射查询按 card_id/admin_user_id/device_id/active/expiry 模拟 entitlement JOIN，并返回 entitlement_id；测试不再用不完整 mock 错误否定实际 SQL 关联逻辑。
6. APP 多卡密组按 admin ID + group ID 去重；一张分组关联多张卡密时保留 card_ids；同一管理员免费分组仍只出现一次，不同管理员数据隔离。
