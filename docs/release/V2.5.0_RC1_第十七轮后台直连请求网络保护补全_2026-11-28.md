## 本轮补全

复核后台 HTML 全部 `fetch()` 调用后，发现登录/注册、初始化诊断、协助会话结束、来源开关、同步、分配/取消分配、访客转换、公告读取、分组重命名和链接撤销等路径仍有直接网络调用，没有经过统一 API wrapper。

本轮在 `releases/v2.5.0-rc1/index.html` 新增 `fetchWithNetworkPolicy()` 并将这些直接 API 请求统一接入：

- GET/HEAD：最多两次尝试；遇网络断开/超时进行一次短间隔重试；502/503/504 进行一次有限重试。
- POST/PUT/PATCH/DELETE：只发送一次，不自动重放；网络中断/超时提示服务器可能已收到操作，先刷新核对再决定是否重试。
- 所有请求 20 秒超时，统一使用已校验的 HTTPS API 根地址、`cache: no-store` 和 `redirect: error`。
- 写入遇 5xx 时提示结果未确认，避免将暂时性服务异常误导为可直接重复提交。
- 原 `api()` 统一包装层与卡密 CSV 导出各自保留专门的 JSON/Blob 处理逻辑；本轮补齐的是其余直连调用点。
